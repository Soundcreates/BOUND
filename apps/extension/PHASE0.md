# Phase 0 browser prototype

Run `node apps/extension/build.mjs` from the repository root, then load `apps/extension/dist` as an unpacked extension in Chromium. In separate terminals, serve `demo/test-dapp` on ports 8000 and 8001 (`python -m http.server 8000 --directory demo/test-dapp` and the same command with `8001`). Open `http://127.0.0.1:8000`, announce the fake wallet, and choose one of the three provider APIs. Use the iframe buttons to see the top-level and requesting-frame origins differ. The extension opens its own warning window; Cancel rejects with EIP-1193 code 4001, while Continue reaches only the fake provider. Rebuild and reload the extension and page after source changes.

After building, `node apps/extension/browser-check.mjs` runs a headless Chromium-family check with fake wallets. The script searches common browser paths on macOS, Linux, and Windows; set `BOUND_CHROMIUM_PATH` to use a specific executable. The browser must support loading unpacked extensions in headless mode. It checks Cancel and Continue across provider APIs, forged and replayed decisions, unmatched bridge replies, wrong message sources and origins, warning-window isolation, request mutation, chain and account changes, cross-origin frames, navigation, poisoned built-ins, service-worker termination, unpatchable and preinstalled providers, unsupported and oversized requests, typed confirmation, the request deadline, and rate limiting. It also demonstrates that a provider reference retained before the hook bypasses mediation. The disposable browser profile is removed afterward. Run `node --test apps/extension/*.test.mjs` for the local service-worker, queue, and adapter checks.

## Feasibility notes

- The test dApp emits EIP-6963 after the extension's `document_start` hook has installed its listener. The hook also attempts an in-place patch of `window.ethereum`.
- The isolated relay creates a per-document channel token and dispatches it synchronously to the MAIN hook. The manifest lists the MAIN hook first; the hook consumes the token before page scripts and consumes replies before page listeners. Page messages can request warnings or cancellation but cannot authorize a decision without the token. The headless Edge checks cover a preinstalled fake provider, an EIP-6963 announcement, an unpatchable provider, one forged decision, and selected built-in poisoning. Other wallets and injection orders remain unverified.
- The service worker gets top-level URL, frame URL, frame ID, tab ID, and document ID from Chrome's message sender. Decisions are accepted only from the extension warning window created for that request. The warning is never page DOM.
- Pending decisions live in service-worker memory. In the headless Edge check, stopping the worker invalidates the decision and cancels the request; the popup remains stale. The worker expires decisions after 45 seconds; the MAIN hook also cancels after 50 seconds.
- The hook captures the JSON, object, collection, promise, message, and timeout intrinsics it uses at `document_start` and clones/freeze-checks request data. The browser check covers selected JSON, object, array, set, and string poisoning after installation.
- The frozen read-only list and `eth_sendRawTransaction` pass untouched. Chain switching and `wallet_addEthereumChain` are treated as unsupported and get an extension-owned choice.
- Snapshot, watcher, and anonymous RPC adapters require settings and remain unverified against live services. ENS root, protocol-attestation, and site-specific chain reads use the anonymizing worker; its configured bootstrap endpoint is contacted directly to fetch and verify the worker. Eligible reads have no direct-RPC fallback. Without a current verified snapshot and baseline the evaluator displays grey.
- Current watcher drift and incident states produce an extension notification and toolbar badge before a wallet request, when data and system notifications are available. The popup also shows status. Notifications can be disabled by the browser or operating system, and asynchronous service reads do not guarantee an alert before a user connects; the live timing gate remains open.
- The anonymous RPC adapter uses the packaged hash-pinned worker harness and a 1.5-second request budget. It has no direct-RPC fallback for eligible reads; the actual offscreen transport still needs live browser verification.
- The observation dispatcher batches and delays reports with randomized alarms and retries. Without a configured watcher endpoint, queued reports remain local. Watcher records are public and the watcher can see the sender's network address.
