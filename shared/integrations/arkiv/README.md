# Arkiv read boundary

`createArkivRpcReader` queries a configured HTTPS RPC for watcher-owned records. It verifies the chain ID (Rabdi 7794095 by default), filters `$owner` and a configured schema tag, keyset-paginates, checks response owner, schema, expiry and record shape, and rejects a page set spanning multiple blocks instead of returning a partial bundle. This strict block policy may require retries on a busy chain. `queryBundle` performs the additional owner and expiry checks using the caller's current block. A schema tag is not authentication.

The entity representation uses an `arkiv.schema` string and a `payload` bytes attribute containing UTF-8 JSON. Arkiv strings are limited to 128 UTF-8 bytes, so JSON is stored in the bytes attribute (up to 128 KiB). The encoding has now passed a funded Rabdi create, patch, owner-query, and expiry run. See [Arkiv's limits](https://docs.arkiv.network/reference/limits/) and [read API](https://docs.arkiv.network/json-rpc/querying-data/).

The owner-wide query is appropriate for the bundled watcher download. It is not a per-site query implementation and does not provide Anon-RPC. No direct per-site or sensitive client lookup should be added here as a fallback. The optional access key is sent in the `x-api-key` header and is not included in error messages. Never commit keys.

On 2026-11-06 an unauthenticated public Rabdi query for the zero address and `bound.record.v1` returned zero records after the reader verified chain 7794095. This confirms a read path and query syntax only; it does not prove writer ownership, expiry, pagination consistency over a real populated dataset, or integration with the extension.

`sender.js` persists signed bytes before broadcast, retries the same transaction after uncertain submission, waits for bounded confirmation when configured, and reconciles already indexed operations. It requires a matching transaction hash, watcher owner, unexpired entity, and record before acknowledging. The testnet harness uses ethers to sign and recover transactions locally; the private key remains in ignored `.env`. The configured system address is the official Rabdi native system address. It returns no runtime bytecode, so `cast code` is not an applicable verification method for this native system call; the documented address, chain ID, `eth_call`, successful receipts, owner events, and readbacks were checked instead. Pending/reverted transactions still need operational reconciliation; no replacement is generated automatically. Signed transaction journals must remain in a private, ignored location. `openArkivArchive` locks its sender, registry, and renewal journals to prevent processes sharing a filesystem from using them concurrently; independently configured writers remain outside that boundary.

`writer.js` adds an idempotent record boundary: it requires an operation-ID lookup, creates only when no prior record exists, reconciles a pending sender journal when the operation is already indexed, and acknowledges only after a public read-back matches owner, payload and expiry. The operation ID is indexed alongside the schema tag and bytes payload.

`codec.js` encodes the proposed named schema, indexed record kind and operation ID, and bytes payload as one Arkiv create operation. Its salt is deterministically derived from the operation ID so rebuilding the same transaction data is stable. Use a random operation ID and a configured lifetime; the codec does not manage nonce, signature, transaction fees, status updates, or storage. On 2026-11-06 a read-only `eth_call` on Rabdi accepted a synthetic create payload produced by this codec and rejected a truncated `execute` call. Reproduce with `scripts/integration/arkiv-call-smoke.mjs`, supplying an HTTPS Rabdi RPC and the system address from the [official Arkiv write documentation](https://docs.arkiv.network/json-rpc/mutating-entities/). The call persists nothing and is not a live-write or receipt test.

The documented system address `0x4400000000000000000000000000000000000044` returns `0x` from `eth_getCode` on Rabdi, consistent with a native system implementation. It is not a deployed EVM bytecode contract; transaction handling was verified through the official interface and live transaction evidence rather than bytecode inspection.

The codec also builds a patch and expiry extension for a previously verified entity key. A live Rabdi patch updated the created baseline in place and its receipt/readback passed owner and payload checks. The archive schedules proactive extensions for registered baselines and statuses, persisting each renewal intent before signing and retrying the same transaction after restart. If an entity nevertheless expires, the upsert registry recreates it on a later update, recording expiry evidence and rechecking it on retry. It fails closed for foreign or modified entities and for a missing legacy entity whose expiry was never recorded. Renewal and rollover have local unit coverage but have not been verified on the live network.

`transport.js` supplies a restricted JSON-RPC transport for watcher-owned writes and readback. `confirm.js` checks receipt status, expected sender and system address, an owner-matching create, patch, or extension event, the canonical block hash, confirmation depth, and the current unexpired entity payload. These checks trust the configured RPC and do not constitute a state proof or finalized-chain guarantee. The owner-filtered operation lookup is an additional check, not an onchain uniqueness constraint. `openArkivArchive` acquires exclusive lock files for its sender, registry, and renewal journals and exposes `close()` to release them. A process crash leaves a lock in place; verify its PID is no longer running before manually removing it. The live create/patch/expiry evidence and transaction hashes are in [feasibility.md](../../contracts/feasibility.md). Replacement of stuck transactions remains open.

`archive.js` composes the owner-filtered reader, restricted transport, receipt verifier, transaction journal, and upsert registry. It creates observations/drift/incidents and maintains one current baseline/status entity per site and chain. `renewBeforeBlocks` sets the renewal threshold, defaulting to one quarter of the shorter configured baseline/status lifetime; it must be positive and smaller than each lifetime. The renewal journal is derived from the registry path with `.renewal` appended and locked with the other journals. Pending renewals are reconciled before other archive writes. Ordinary same-hour status regressions are rejected; guarded recovery uses a captured status version so stale retries cannot overwrite a newer committed status. An expired entity is replaced only after a fresh owner/content check or, when absent, after its locally recorded verified expiry. A legacy registry without that expiry requires operator reconciliation if the entity has disappeared. It requires explicit lifetimes, separate journal paths, and injected signing, transaction inspection, and transaction hashing. The writer key must be dedicated to this process; an unresolved prepared transaction blocks new signing. The system address and chain must be independently verified. Local composition tests use fake RPC and signatures.
