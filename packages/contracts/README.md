# Phase 0 contract draft

From a clean checkout with Node.js 22 or newer, run `npm test`. No install is needed. This package exports dependency-free validators and `parseUniqueJSON`, which rejects duplicate object keys before schema validation. Validators check structure; they do not establish data authenticity, currentness, canonical serialization, or trust. Consumers must apply the security checks owned by their lane.

## Proposed wire shapes

The ENS `bound.root.v2` record is `{schemaVersion, network, epoch, digest, arkivKey, arkivOwner}`. It points to an Arkiv `trust_snapshot` record whose `canonical` string contains the canonical snapshot bytes. Readers check the Arkiv metadata owner and expiry, then verify the snapshot digest against ENS. Snapshot schema remains version 1 and uses `{schemaVersion, network, epoch, generatedAt, expiresAt, sharedContracts, sites}`. Site chains contain `trustedCounterparties`, `trustedCalledContracts`, `deployerLineage`, and `sourceEvidence`. Addresses are lower-case; lists requiring order are strictly sorted and unique. Times are UTC ISO strings with optional millisecond precision; chain IDs are safe positive integers or decimal object keys. Source evidence is structural only; consumers must validate provenance.

The observation intake is `{site, kind, value, chainId, reporterKey}`, with kind `counterparty`, `called-contract`, or `warned`. Public Arkiv payloads have `schemaVersion`, `kind`, `site`, `chainId` and kind-specific fields. Drift and incident payloads point to an Arkiv `evidence` record containing the report bytes and digest. A bundle contains entity envelopes with Arkiv key, owner, expiry block, and a baseline, drift, incident, or status payload. The caller must supply the configured watcher address and current Arkiv block; foreign-owner and expired records are rejected. Arkiv owner and expiry are metadata, not payload fields. A self-asserted owner is never sufficient.

The contract tests verify the snapshot fixture's canonical bytes and Keccak-256 digest offline. `packages/contracts/verify-digest.sh` independently checks the fixture against Rabdi's `web3_sha3` RPC. General RFC 8785 behavior still needs validation by Developer 2's implementation. `fixtures/contracts/verdict-matrix.json` captures score caps and a normal-router false-hold control; it is a conformance specification, not an implemented evaluator.

The batch wraps 1–100 events in `{schemaVersion, events}`. The response is `{schemaVersion, result}` with accepted, retry, or rejected. The watcher validates the whole batch and persists its eligible events together; events for active incidents and duplicates are skipped. A retry can follow an uncertain acknowledgement, so the watcher deduplicates repeated events. This package defines the wire contract; the intake server is in `services/watcher`. The local decision shape is `{coverage, evaluated, bypassPossible, verdict, score}`. Unsupported or unevaluated requests have no verdict or score, and grey has no score. This is extension state, never a page-provided authorization. Adapter results use `{service, status, source, data}`; a success envelope does not authenticate its contents, and failures contain no facts or direct-RPC fallback.

## Items for shared Phase 0 acceptance

The Dev3 shapes are proposed until Developers 1 and 2 accept the field names and package interfaces. Still to freeze: lineage evidence details, Arkiv schema tags and record lifetimes, reporter-key encoding, bundle ordering, batch atomicity and retry behavior, ENS name/key, K and the counting window, N/M and score weights, and the minimum Anon-RPC coverage. The hierarchy for protocol self-attestation is contradictory across the architecture and needs a live proof. Network and test-writer evidence is recorded in `feasibility.md`. Fixtures and public read probes do not pass any live write, expiry, or controlled-domain gate.

`eth_sendRawTransaction` is separately classified because it broadcasts. `wallet_addEthereumChain` remains unsupported pending agreement. Unknown methods require an explicit warning. The provisional allowlist is in `index.js`.

**Proposed status clarification:** an incident status may have `incidentReference: null` while the Arkiv incident entity is unavailable; consumers keep the incident warning and disable the report link. Non-incident status must have a null reference. The Arkiv evidence entity carries the report payload and digest.

The raw JSON parser rejects duplicate keys and lone UTF-16 surrogates. Callers must first decode incoming bytes as strict UTF-8; this parser accepts a JavaScript string and cannot detect bytes that were previously replaced during decoding. Snapshot canonicalization, hashing, freshness and rollback checks remain the trust lane's responsibility.
